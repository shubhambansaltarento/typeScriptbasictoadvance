type / interface / union

type and interface both describe the shape of a value. Most of the time they're interchangeable for plain objects - the differences only matter once you reach for composition, or need declaration merging.

type: object shapes and aliases

type can name any shape, not just objects - including a primitive alias like type UserId = number.

type: composing with intersections (&)

type ProductWithStock = Product & { stock: number } combines two shapes into one. This is the main reason to reach for type over interface: intersections, unions, and tuples are all things a plain interface cannot express on its own.

type: unions and tuples

A union ("pending" | "success" | "failed") says a value is one of several fixed options. A tuple ([number, number]) is a fixed-length array where each position has its own type.

interface: object shapes

interface reads almost identically to an object type, but is meant specifically for describing the shape of objects (and can be extended by other interfaces).

interface: declaration merging

Declare an interface with the same name twice, and TypeScript merges both declarations into one shape. A type alias can never do this - redeclaring a type name is always an error.

Practical rule

For simple object models (frontend/API shapes), either works - interface is a perfectly reasonable default. Reach for type as soon as you need a union, an intersection, or a tuple.
