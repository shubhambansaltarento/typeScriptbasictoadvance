readonly

readonly prevents reassignment through that type.

interface Product {
  readonly id: number;
  name: string;
}

const product: Product = { id: 101, name: "Laptop" };

product.name = "MacBook"; // works

product.id = 200;
// ❌ Cannot assign to 'id' because it is a read-only property

Very useful for entities - the ID should generally not be changed after creation:

interface User {
  readonly id: string;
  name: string;
}

Important limitation

readonly is a TypeScript compile-time restriction. It doesn't magically freeze the JavaScript object at runtime. For actual runtime immutability, Object.freeze(product) is a different mechanism.
